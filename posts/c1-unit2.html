Prácticas básicas de Playwright con Python

24/08/2026 Práctica Nivel: Intermedio

Tres ejercicios progresivos para comprender cómo Playwright abre un navegador, navega por una página, localiza elementos, interactúa con ellos y valida resultados mediante Python.

1. Qué vamos a practicar

Ya tenemos preparado el entorno de ejecución: Debian 13, Python 3.13, un entorno virtual y Playwright 1.62.0 con Chromium instalado.

Ahora dejamos de comprobar solamente que Playwright funciona y empezamos a utilizarlo como herramienta de automatización.

La progresión de las prácticas será deliberadamente sencilla:

  • Abrir una página y comprobar información de ella.
  • Localizar elementos dentro del DOM.
  • Interactuar con un formulario y validar su contenido.

La idea fundamental es aprender a razonar cada automatización antes de escribir código. Primero identificamos qué queremos comprobar o manipular y después buscamos el elemento adecuado dentro de la página.

El modelo mental básico será:

text
Navegador
└── Página
└── Elementos
└── Localizar
└── Interactuar
└── Validar

Esta cadena es la base de prácticamente cualquier automatización web con Playwright.

2. Ejercicio 1: navegación y validación

El primer ejercicio responde a una pregunta muy sencilla: ¿podemos abrir una página, leer información de ella y comprobar que el resultado es el esperado?

Comenzamos importando la API síncrona de Playwright:

python
# Importamos la API síncrona de Playwright.
# Nos permite ejecutar las operaciones de forma secuencial.
from playwright.sync_api import sync_playwright

# Iniciamos Playwright.
with sync_playwright() as p:
    # Lanzamos Chromium en modo headless.
    browser = p.chromium.launch(headless=True)

    # Creamos una nueva página.
    page = browser.new_page()

    # Navegamos hasta Google.
    page.goto("https://google.com")

    # Obtenemos el título de la página.
    print("Titulo:", page.title())

    # Localizamos el elemento h1 y obtenemos su texto.
    print("H1:", page.locator("h1").inner_text())

    # Comprobamos que el título obtenido coincide con el esperado.
    assert page.title() == "Google"

    # Comprobamos que el h1 contiene el texto esperado.
    assert page.locator("h1").inner_text() == "Antes de ir a Google"

    # Si ninguna validación falló, mostramos que la prueba terminó correctamente.
    print("Test 1 Ok")

    # Cerramos el navegador.
    browser.close()

La primera operación importante es goto(). Su función es ordenar al navegador que navegue hasta una URL.

Después utilizamos page.title() para obtener el título HTML de la página.

Para obtener contenido del DOM utilizamos un locator. En este caso:

python
page.locator("h1")

Esto no significa que Playwright esté buscando visualmente el texto. Estamos indicando que queremos localizar elementos HTML cuyo selector CSS sea h1.

Finalmente utilizamos assert. Esta instrucción convierte nuestra expectativa en una validación automática.

Si la condición es verdadera, la ejecución continúa. Si es falsa, Python lanza un AssertionError y la prueba falla.

3. Analizar el error del ejercicio 1

Durante la práctica cometimos deliberadamente dos errores diferentes y ambos son importantes porque enseñan conceptos fundamentales.

El primero fue escribir:

python
page.tittle()

El método correcto es:

python
page.title()

El error AttributeError apareció porque el objeto Page no posee ningún método llamado tittle(). Python incluso indicó que probablemente queríamos utilizar title().

Después corregimos el método, pero dejamos una expectativa incorrecta:

python
assert page.title() == "google.com"

El navegador devolvía:

text
Google

Por tanto, Python evaluó:

python
"Google" == "google.com"

El resultado es False, por lo que assert provocó un AssertionError.

Esto nos enseña una diferencia fundamental: Playwright puede estar funcionando perfectamente y aun así nuestra prueba puede fallar porque la expectativa escrita por nosotros es incorrecta.

El razonamiento correcto es siempre:

text
Resultado real → ¿Qué devuelve la página?
Resultado esperado → ¿Qué debería devolver?
Validación → ¿Son iguales?

4. Ejercicio 2: localizar elementos

En el segundo ejercicio cambiamos el objetivo. Ya no queremos comprobar solamente información de la página. Ahora queremos encontrar un elemento concreto dentro del DOM.

Utilizamos TikTok como página de prueba y buscamos el elemento relacionado con el inicio de sesión.

El concepto fundamental es locator.

python
login = page.get_by_text("Log in")

En este caso estamos indicando a Playwright que localice elementos cuyo contenido textual sea Log in.

Después podemos preguntar cuántos elementos coinciden con ese localizador:

python
print("Login encontrado:", login.count())

Durante la prueba vimos que TikTok tenía varios elementos que coincidían con ese texto. El resultado fue:

text
Login encontrado: 4

Eso demuestra que el localizador encontró elementos reales dentro del DOM.

La validación utilizada fue:

python
assert login.count() > 0

La condición significa: debe existir al menos un elemento que coincida con nuestro localizador.

También comprobamos qué elementos podía leer Playwright utilizando:

python
print(page.locator("body").all_inner_texts())

Esto nos permitió observar que la página realmente contenía varios textos relacionados con Log in.

La prueba completa quedó conceptualmente así:

python
# Abrimos TikTok.
page.goto("https://www.tiktok.com")

# Buscamos elementos cuyo texto sea "Log in".
login = page.get_by_text("Log in")

# Mostramos cuántos elementos coinciden.
print("Login encontrado:", login.count())

# Validamos que exista al menos uno.
assert login.count() > 0

# Indicamos que el ejercicio terminó correctamente.
print("Test 2 - elemento encontrado")

5. Analizar el localizador

Durante la práctica intentamos reutilizar el mismo criterio sobre Google.

El problema fue que nuestra búsqueda estaba basada en el texto:

python
page.get_by_text("Log in")

Google utiliza otro texto para ese elemento en nuestra sesión:

text
Iniciar sesión

Por eso el resultado fue cero coincidencias.

Esto es importante porque un localizador no busca nuestra intención. Busca exactamente el criterio que le proporcionamos.

Por tanto, antes de automatizar debemos inspeccionar la página y determinar qué atributo, texto, rol o estructura identifica realmente al elemento.

El razonamiento debe comenzar siempre por la página:

text
¿Qué elemento necesito?
↓
¿Cómo está identificado en el DOM?
↓
¿Qué locator representa mejor esa identificación?
↓
¿Existe realmente?
↓
¿Puedo interactuar con él?

6. Ejercicio 3: formularios

El tercer ejercicio introduce interacción. Ya no solamente observamos la página: modificamos el estado de un elemento.

Utilizamos el buscador de Google.

Primero localizamos el campo de búsqueda:

python
buscador = page.locator("textarea[name='q']")

El selector combina dos criterios: el elemento HTML textarea y el atributo name="q".

Una vez localizado podemos introducir información mediante fill():

python
buscador.fill("Playwright Python")

Después comprobamos qué valor tiene realmente el campo utilizando input_value():

python
print("Texto introducido:", buscador.input_value())

Finalmente convertimos esa comprobación en una validación automática:

python
assert buscador.input_value() == "Playwright Python"

El script completo quedó así:

python
# Importamos la API síncrona de Playwright.
from playwright.sync_api import sync_playwright

# Iniciamos Playwright.
with sync_playwright() as p:
    # Lanzamos Chromium en modo headless.
    browser = p.chromium.launch(headless=True)

    # Creamos una nueva página.
    page = browser.new_page()

    # Navegamos hasta Google.
    page.goto("https://www.google.com")

    # Localizamos el campo de búsqueda.
    buscador = page.locator("textarea[name='q']")

    # Introducimos texto en el campo.
    buscador.fill("Playwright Python")

    # Leemos el valor actual del campo.
    print("Texto introducido:", buscador.input_value())

    # Validamos que el valor sea exactamente el esperado.
    assert buscador.input_value() == "Playwright Python"

    # Confirmamos que la prueba terminó correctamente.
    print("Test 3 - formulario OK")

    # Cerramos el navegador.
    browser.close()

El resultado obtenido fue:

text
Texto introducido: Playwright Python
Test 3 - formulario OK

Con este ejercicio ya tenemos las tres operaciones fundamentales: localizar, interactuar y validar.

7. Flujo mental de Playwright

Los tres ejercicios permiten construir un procedimiento de razonamiento que podemos reutilizar en automatizaciones más complejas.

No comenzamos escribiendo código. Primero analizamos qué queremos conseguir.

text
1. Abrir la página
↓
2. Identificar el elemento
↓
3. Elegir un locator fiable
↓
4. Ejecutar una acción
↓
5. Obtener el resultado
↓
6. Compararlo con lo esperado
↓
7. Determinar si la prueba pasa o falla

En términos de Playwright, este flujo se traduce normalmente en:

python
page.goto("URL")
elemento = page.locator("selector")
elemento.fill("valor")
resultado = elemento.input_value()
assert resultado == "valor"

El código es solamente la representación final del razonamiento. La parte importante es saber qué elemento necesitamos, cómo identificarlo y qué resultado esperamos obtener.

8. Qué hemos aprendido

En estas tres prácticas hemos construido una primera base real de automatización web con Playwright.

  • sync_playwright(): inicia la API síncrona de Playwright.
  • p.chromium.launch(): inicia Chromium.
  • browser.new_page(): crea una página.
  • page.goto(): navega hacia una URL.
  • page.title(): obtiene el título de la página.
  • page.locator(): localiza elementos mediante selectores.
  • get_by_text(): localiza elementos mediante contenido textual.
  • count(): cuenta coincidencias de un localizador.
  • fill(): introduce contenido en un campo.
  • input_value(): obtiene el valor actual de un campo.
  • assert: convierte una expectativa en una validación automática.

También aprendimos algo igual de importante: un error de automatización no significa necesariamente que Playwright esté roto.

Puede fallar el selector, puede ser incorrecta la expectativa o simplemente podemos haber escrito mal el nombre de un método.

La prueba debe analizarse siempre desde el resultado real que devuelve la aplicación.

text
Playwright funciona
↓
El navegador funciona
↓
La página carga
↓
Localizamos el elemento
↓
Interactuamos con él
↓
Validamos el resultado

Esta es la base sobre la que posteriormente podremos construir pruebas de autenticación, navegación, formularios complejos, scraping controlado, validaciones de interfaces y suites completas de testing E2E.
