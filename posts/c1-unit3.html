Automatización de inicio de sesión con Playwright y Python

24/08/2026 Práctica Nivel: Intermedio

Automatización de un flujo real de inicio de sesión con Playwright y Python utilizando una interfaz gráfica. La práctica introduce sincronización, localizadores, elementos superpuestos, formularios y validación de acciones.

1. Qué vamos a practicar

En las prácticas anteriores utilizamos Playwright para navegar por páginas, localizar elementos, interactuar con formularios y realizar validaciones sencillas.

En esta práctica aumentamos la complejidad y construimos un flujo completo de autenticación utilizando la interfaz gráfica del navegador.

El objetivo es automatizar el proceso desde que se abre la página hasta que se pulsa el botón de inicio de sesión después de introducir las credenciales.

El flujo que construiremos será:

text
Abrir TikTok
↓
Cerrar "Got it"
↓
Rechazar cookies opcionales
↓
Pulsar "Log in"
↓
"Use phone or email"
↓
"Use email or username"
↓
Localizar credenciales
↓
Introducir usuario y contraseña
↓
Esperar activación del botón
↓
Pulsar "Log in"

La diferencia respecto a las prácticas anteriores es que ahora varios elementos de la interfaz pueden cambiar de estado durante la ejecución.

Por tanto, no basta con localizar un elemento. También tenemos que comprobar que está preparado para recibir una interacción.

2. Preparar la interfaz

Comenzamos utilizando la API síncrona de Playwright y lanzando Chromium con interfaz gráfica.

python
# Importamos Playwright.
from playwright.sync_api import sync_playwright

# Credenciales que se establecerán antes de ejecutar la práctica.
USERNAME = "TU_USUARIO_O_CORREO"
PASSWORD = "TU_CONTRASEÑA"

# URL de la aplicación.
URL = "https://www.tiktok.com"

with sync_playwright() as p:
     browser = p.chromium.launch(headless=False)
     page = browser.new_page()
     page.goto(URL)
     page.wait_for_timeout(3000)

Utilizamos headless=False porque esta práctica está orientada a observar el comportamiento de la interfaz gráfica mientras Playwright ejecuta las acciones.

Una vez cargada la página debemos eliminar los elementos que pueden impedir la interacción con el contenido principal.

El primero fue el mensaje Got it.

python
got_it = page.get_by_role(
    "button",
    name="Got it"
)

if got_it.count() > 0:
    got_it.first.click()

La condición evita que el script falle cuando ese elemento no aparece.

Después hacemos lo mismo con el banner de cookies.

python
cookies = page.get_by_role(
    "button",
    name="Decline optional cookies"
)

if cookies.count() > 0:
    cookies.first.click()

Esto resultó especialmente importante porque durante las pruebas comprobamos que el banner podía interceptar los eventos de puntero destinados a otros elementos.

3. Localizar Login

Una vez preparada la interfaz buscamos el botón de inicio de sesión.

python
login = page.get_by_role(
    "button",
    name="Log in"
)

print(
    "Log in encontrados:",
    login.count()
)

assert login.count() > 0

login.first.click()

Durante las pruebas observamos que podía existir más de un elemento con el mismo nombre.

Por eso primero comprobamos el número de coincidencias mediante count() y después utilizamos first para seleccionar la primera coincidencia.

El resultado obtenido durante una ejecución correcta fue:

text
Log in encontrados: 2

Después de pulsar el botón esperamos a que aparezca el panel de autenticación.

python
page.wait_for_timeout(3000)

4. Seleccionar teléfono o correo

El primer panel de autenticación no muestra directamente el formulario de usuario y contraseña.

Debemos seleccionar la opción:

text
Use phone or email

Utilizamos un localizador basado en el texto visible.

python
phone_email = page.get_by_text(
    "Use phone or email",
    exact=True
)

print(
    "Use phone or email encontrados:",
    phone_email.count()
)

assert phone_email.count() > 0

phone_email.first.click()

El resultado correcto fue:

text
Use phone or email encontrados: 1
Test 5 - Use phone or email pulsado

Después de esta acción aparecen los campos asociados a teléfono, código y contraseña.

text
Inputs encontrados: 4
0 type: search placeholder: Search
1 type: text placeholder: Phone number
2 type: text placeholder: Enter 6-digit code
3 type: password placeholder: None

5. Seleccionar email o username

Como el objetivo de esta práctica es utilizar usuario o correo electrónico y contraseña, debemos cambiar el método de autenticación.

La interfaz proporciona la opción:

text
Use email or username

La localizamos y comprobamos que realmente exista antes de pulsarla.

python
email_username = page.get_by_text(
    "Use email or username",
    exact=True
)

print(
    "Use email or username encontrados:",
    email_username.count()
)

assert email_username.count() > 0

email_username.first.click()

La ejecución correcta produjo:

text
Use email or username encontrados: 1
Test 6 - Use email or username pulsado

Ahora la interfaz cambia y aparecen los campos que necesitamos.

6. Localizar las credenciales

Después de seleccionar el método correcto inspeccionamos los campos disponibles.

python
inputs = page.locator("input")

print(
    "Inputs después de seleccionar email:",
    inputs.count()
)

for i in range(inputs.count()):
    element = inputs.nth(i)

    print(
        i,
        "type:",
        element.get_attribute("type"),
        "placeholder:",
        element.get_attribute("placeholder")
    )

El resultado fue:

text
Inputs después de seleccionar email: 3
0 type: search placeholder: Search
1 type: text placeholder: Email or username
2 type: password placeholder: Password

Esto nos permite distinguir el buscador general de la página de los dos campos pertenecientes al formulario de autenticación.

En lugar de depender de la posición numérica de los elementos, utilizamos sus atributos visibles.

python
username = page.get_by_placeholder(
    "Email or username"
)

password = page.get_by_placeholder(
    "Password"
)

Esta estrategia es más clara que seleccionar simplemente el segundo y tercer input, porque expresa directamente qué campo queremos utilizar.

7. Introducir las credenciales

Las credenciales se mantienen como variables globales al principio del script.

python
USERNAME = "TU_USUARIO_O_CORREO"
PASSWORD = "TU_CONTRASEÑA"

De esta forma el flujo de automatización no necesita modificarse cada vez que cambiamos las credenciales utilizadas durante la práctica.

Utilizamos fill() para introducir los valores.

python
username.fill(USERNAME)
password.fill(PASSWORD)

print("Credenciales introducidas")

En la ejecución correcta obtuvimos:

text
Credenciales introducidas

En este punto todavía no pulsamos el botón. Primero debemos considerar el estado de la interfaz.

8. Activar y pulsar Login

Durante las pruebas encontramos un comportamiento importante: el botón Log in puede encontrarse inicialmente deshabilitado.

Después de introducir las credenciales, la interfaz necesita un pequeño intervalo para actualizar su estado y habilitar la acción.

Por eso el flujo final incorpora una espera de dos segundos después de rellenar los campos.

python
username.fill(USERNAME)
password.fill(PASSWORD)

print("Credenciales introducidas")

page.wait_for_timeout(2000)

login = page.get_by_role(
    "button",
    name="Log in"
)

assert login.count() > 0

login.last.click()

print("Test 7 - Login pulsado")

El resultado confirmado de la ejecución fue:

text
Log in encontrados: 2
Use phone or email encontrados: 1
Test 5 - Use phone or email pulsado
Use email or username encontrados: 1
Test 6 - Use email or username pulsado
Credenciales introducidas
Test 7 - Login pulsado

En este punto el flujo automatizado llegó correctamente hasta la acción final del formulario.

9. Errores encontrados durante la práctica

Esta práctica fue especialmente útil porque el flujo no funcionó correctamente en el primer intento.

Los errores permitieron identificar varios problemas habituales en automatización web.

9.1. El elemento existe pero no recibe el clic

En una de las ejecuciones Playwright encontró correctamente el botón Log in, pero el clic terminó en un TimeoutError.

El registro de Playwright indicaba que otro elemento estaba interceptando los eventos de puntero.

text
element is visible, enabled and stable
...
intercepts pointer events

El problema no era el localizador. El elemento existía y Playwright podía encontrarlo. El problema era el estado de la interfaz: el banner de cookies todavía estaba interceptando los eventos.

9.2. El selector puede devolver cero elementos

También encontramos ejecuciones donde:

text
Log in encontrados: 0

y la validación:

python
assert login.count() > 0

provocaba un AssertionError.

Esto demuestra por qué una automatización debe considerar el estado real de la página antes de asumir que un elemento siempre estará disponible inmediatamente.

9.3. El botón de Login cambia de estado

Otro comportamiento importante apareció al final del formulario.

El botón podía estar presente en el DOM pero todavía no estar preparado para ejecutar la acción porque las credenciales acababan de ser introducidas.

La solución utilizada en la práctica fue esperar dos segundos después de rellenar los campos antes de ejecutar el clic.

9.4. El idioma afecta al texto visible

Durante la inspección observamos que el botón podía mostrarse como Log in, aunque conceptualmente la acción fuera "Continuar" dependiendo del idioma de la interfaz.

Por ese motivo el selector utilizado durante nuestra ejecución se basó en el texto que Playwright estaba observando realmente:

python
page.get_by_role(
    "button",
    name="Log in"
)

10. Flujo mental de una automatización de login

Esta práctica introduce una idea importante: automatizar una interfaz no significa simplemente reproducir una secuencia de clics.

Cada acción depende del estado actual de la página.

text
Página cargada
↓
¿Existe "Got it"?
↓
Eliminarlo si existe
↓
¿Existe banner de cookies?
↓
Eliminarlo si existe
↓
Localizar Login
↓
Abrir autenticación
↓
Seleccionar método
↓
Localizar campos
↓
Introducir datos
↓
Esperar actualización del estado
↓
Ejecutar Login

La diferencia respecto a un script que simplemente hace clics consiste en que cada paso se apoya en una condición observable de la interfaz.

El patrón general es:

text
Localizar
↓
Comprobar
↓
Interactuar
↓
Esperar estado
↓
Validar

11. Qué hemos aprendido

En esta práctica pasamos de automatizaciones sencillas a un flujo de interacción compuesto por múltiples estados.

  • headless=False: permite observar la ejecución mediante la interfaz gráfica.
  • get_by_role(): permite localizar elementos utilizando su rol accesible y nombre.
  • get_by_text(): permite localizar opciones mediante el texto visible.
  • get_by_placeholder(): permite localizar campos de formulario mediante su placeholder.
  • count(): permite conocer cuántos elementos coinciden con un locator.
  • first y last: permiten seleccionar una coincidencia concreta cuando existen varias.
  • fill(): permite introducir información en campos de formulario.
  • wait_for_timeout(): permite introducir una espera explícita durante una práctica controlada.
  • assert: permite convertir una condición esperada en una validación automática.

También aprendimos que encontrar un elemento no significa necesariamente que podamos interactuar inmediatamente con él.

La página puede contener banners, overlays, diálogos u otros elementos que intercepten los eventos.

Por tanto, el análisis de una automatización debe considerar tanto el DOM como el estado visible de la interfaz.
